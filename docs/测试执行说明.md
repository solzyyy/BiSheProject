# 测试执行说明

本文档将答辩前的最小测试集收束为 4 项，兼顾可复现性和现场可操作性。

---

## 一、全链路烟雾测试

目标：验证系统能够从原始文本走到最终游戏工程。

推荐方式：

```bash
python -m src.cli demo
```

建议按阶段顺序执行 1 到 23 步，并记录以下信息：

- 是否成功生成 `out/extract_chain.json`
- 是否成功生成 `out/canonical_branch.json`
- 是否成功生成 `out/all_paths_completed/`
- 是否成功生成 `out/enhanced_paths/`
- 是否成功生成 `wangfo/game/`

验收标准：

- 无关键步骤报错退出
- 最终 `wangfo/game/` 可被 Ren'Py 打开
- 至少得到 1 条主线和 1 条分支路径

---

## 二、中间产物结构校验

目标：验证关键 JSON 和目录是否存在且结构基本正确。

执行命令：

```bash
python -m src.cli validate-outputs --mode all
```

当前脚本位置：

- `scripts/validate_pipeline_outputs.py`

主要检查内容：

- `out/extract_chain.json`
- `out/entities.json`
- `out/state_baseline.json`
- `out/canonical_branch.json`
- `out/decision_points_analysis.json`
- `out/branches.json`
- `out/all_paths_completed/`
- `out/enhanced_paths/`
- `wangfo/game/`

验收标准：

- 所有关键文件存在
- JSON 可解析
- 实体规范名与别名无明显冲突
- 主脚本包含 `label start` 和 `jump canonical_path`

---

## 三、Ren'Py 可运行性验证

目标：验证最终游戏工程对答辩展示可用。

执行命令：

```bash
python -m src.cli validate-outputs --mode game
```

然后人工试玩以下 2 条路线：

1. 主线路径：从 `canonical_path` 正常进入并推进。
2. 分支路径：任选 1 个分支选项，确保可正常跳转到对应结局。

建议同时检查：

- 路径脚本数量是否正常
- 结局脚本数量是否正常
- 角色定义文件和背景图映射文件是否存在

验收标准：

- 游戏可启动
- 主线可进入
- 至少 1 个分支可跳转到结局
- 无明显缺图、缺角色、缺标签错误

---

## 四、第二文本轻量验证

目标：证明系统并非只适配《王佛脱险记》单一文本。

### 第一步：抽取第二文本样本

```bash
python -m src.cli extract-story-sample --title "马尔戈的微笑"
```

默认输出：

- `docs/validation_samples/马尔戈的微笑.txt`

### 第二步：建议执行的轻量流程

至少执行以下前半段步骤：

```bash
python -m src.cli extract-events --input "docs/validation_samples/马尔戈的微笑.txt"
python -m src.cli generate-mentions
python -m src.cli generate-entities
```

如时间允许，可继续补充：

```bash
python -m src.cli extract-character-states
python -m src.cli extract-world-states
python -m src.cli extract-relationship-states
```

验收标准：

- 第二文本能够成功产出结构化事件
- 能生成实体与基础状态结果
- 输出不依赖《王佛脱险记》的专有文件名或固定剧情标签

---

## 五、统计结果更新

在完成上述测试后，统一更新答辩与论文的统计口径：

```bash
python -m src.cli collect-metrics --write-markdown docs/答辩实验结果.md
```

当前统计脚本位置：

- `scripts/collect_project_metrics.py`

当前统一引用文件：

- `docs/答辩实验结果.md`

---

## 六、推荐顺序

1. 先运行 `validate-outputs --mode game`，确保最终演示不翻车。
2. 再运行 `collect-metrics`，更新答辩与论文统计表。
3. 若要展示完整工程能力，再执行 `validate-outputs --mode all`。
4. 最后补做第二文本轻量验证，回答“是否只适配单一文本”的追问。
